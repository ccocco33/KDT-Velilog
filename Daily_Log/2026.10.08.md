## 1. D Flip-Flop vs D Latch

| 구분 | D Latch | D Flip-Flop |
|---|---|---|
| 동작 | **레벨 트리거** (enable/clk가 1인 동안 계속 D가 Q로 통과 = transparent) | **엣지 트리거** (clk 상승/하강 순간에만 D를 샘플링) |
| 구조 | 게이트 몇 개 | 래치 2개(master-slave) → 더 큼 |
| 타이밍 분석 | 어려움 (time borrowing) | 쉬움 → **동기 설계의 기본 소자** |
| Verilog | `always @(*) if (en) q = d;` | `always @(posedge clk) q <= d;` |

```verilog
// D Latch
always @(*)
    if (en) q = d;            // en=0이면 이전 값 유지 → latch

// D Flip-Flop (비동기 리셋)
always @(posedge clk or negedge rst_n)
    if (!rst_n) q <= 1'b0;
    else        q <= d;
```

### 플립플롭 핵심 타이밍 파라미터
```
          setup  hold
         |<--->|<->|
D  ======X=====[안정]====X=====
              ↑
CLK ________|‾‾‾‾‾‾‾‾‾‾
              |<-tclk-q->|
Q  ====================X======
```
- **Setup time (tsu)**: 클럭 엣지 **전에** D가 안정돼 있어야 하는 최소 시간
- **Hold time (th)**: 클럭 엣지 **후에** D가 유지돼야 하는 최소 시간
- **Clock-to-Q (tclk-q)**: 엣지 후 Q가 바뀌기까지 걸리는 시간
- setup/hold를 위반하면 → **메타스테이빌리티(metastability)**: Q가 0도 1도 아닌 중간 전압에 한동안 머무르다가 랜덤하게 0 또는 1로 결정됨

## 2. ⭐ CDC (Clock Domain Crossing) — 면접 필수 질문

**정의**: 한 클럭 도메인에서 만든 신호를 **다른 클럭 도메인의 플립플롭이 샘플링**하는 것.
두 클럭의 위상 관계를 알 수 없으면 setup/hold 위반을 피할 수 없어 메타스테이빌리티가 발생한다.

### 2.1 클럭 관계별 분류

```
동일 clock source ─┬─ 동일 phase ──────────────→ CDC 아님 (완전 동기)
                   └─ phase 다름 ──────────────→ (부분적) CDC
                                                  위상 관계가 고정되어 있어
                                                  STA로 분석 가능한 경우가 많음

다른 clock source ─┬─ 동일 주파수, phase 다름 ──→ CDC
                   │   (위상이 계속 조금씩 흘러감)
                   └─ 다른 주파수 ─┬─ 빠름 → 느림 : 데이터 **놓침(loss)** 위험
                                   └─ 느림 → 빠름 : **메타스테이블 확률 높음**
```

- **빠른 → 느린 도메인**: 빠른 쪽의 짧은 펄스(1클럭짜리)가 느린 클럭 엣지 사이에 끼어 **아예 안 보일 수 있음** → 펄스를 늘리거나 handshake 필요
- **느린 → 빠른 도메인**: 수신 쪽 클럭이 빠를수록 샘플링 횟수가 많아 메타스테이블 발생 빈도↑, 그리고 메타스테이블이 풀릴 시간(1클럭 주기)이 짧아짐

> 💡 MTBF(평균 고장 간격) 공식
> `MTBF = e^(tr/τ) / (T0 · f_clk · f_data)`
> - `tr`: 메타스테이블이 풀리는 데 허용된 시간 (≈ 수신 클럭 주기)
> - `f_clk`(수신 클럭), `f_data`(데이터 변화율)가 클수록 MTBF↓
> - synchronizer 단수를 늘리면 `tr`이 커져 MTBF가 **지수적으로** 증가 → 2단이면 대부분 충분, 고속이면 3단

### 2.2 칩 간 통신 = 결국 CDC
- 칩과 칩이 데이터를 주고받으면 각자 클럭이 다르므로 결국 CDC 발생
- 인터페이스 예: **UART**(클럭선 없음 → 수신측이 16배 오버샘플링), **SPI**(SCLK 동반), **I2C**(SCL 동반)
- 외부 입력도 마찬가지: **스위치/버튼** 입력은 클럭과 무관하게 바뀜 → FF의 **D 입력이 스위치 값**이므로 언제든 setup/hold 위반 가능 → synchronizer 필수 (지난 시간 debouncer 앞단)

### 2.3 해결 방법

| 방법 | 대상 | 특징 |
|---|---|---|
| **2-stage F/F Synchronizer** | **1bit** 레벨 신호 | 가장 기본, I/O 쪽 대부분 사용 |
| **Pulse Synchronizer** (toggle sync) | 1bit 펄스 | 펄스 → 토글로 바꿔 동기화 후 엣지 검출 |
| **비동기 FIFO** | **멀티 bit** 연속 데이터 | 처리량 높음, Gray 코드 포인터 |
| **MCP / Handshake** | 멀티 bit, 가끔 전송 | 응답(ack) 올 때까지 데이터 유지, 느리지만 간단 |

#### ① 2-FF Synchronizer
```verilog
// clk_b 도메인으로 1bit 신호 가져오기
reg sync1, sync2;
always @(posedge clk_b or negedge rst_n)
    if (!rst_n) {sync2, sync1} <= 2'b00;
    else        {sync2, sync1} <= {sync1, sig_a};
// sync2만 사용. sync1은 메타스테이블일 수 있으니 절대 직접 쓰지 않기
```
- 메타스테이빌리티를 **없애는 게 아니라 확률을 낮추는** 것
- 두 FF 사이에는 조합 논리를 넣지 않는다 (해소 시간을 깎아먹음)
- 원래 신호(sig_a)는 **송신 도메인에서 FF 출력**이어야 함 (조합 논리 출력이면 글리치까지 넘어감)

#### ② 멀티 bit에 2-FF를 각각 달면 안 되는 이유 ⚠️
```
4'b0111 → 4'b1000 으로 바뀌는 순간 샘플링
각 비트의 지연이 조금씩 달라 → 1111, 0000, 1010 ... 등 엉뚱한 값을 읽을 수 있음
```
→ 비트별로는 정상 동기화돼도 **값 전체의 일관성(coherency)**이 깨짐
→ 해결: Gray 코드(1비트만 바뀜), FIFO, MCP/handshake

#### ③ FIFO
- **동기식 FIFO**: 쓰기/읽기가 **같은 클럭** → CDC 해결용이 아니라 속도 차이를 흡수하는 **버퍼**
- **비동기식 FIFO**: 쓰기/읽기 **클럭이 다름** → **CDC 해결용**
  - 쓰기 포인터/읽기 포인터를 **Gray 코드**로 바꿔 상대 도메인에 2-FF로 동기화 → full/empty 판단
  - (지난 시간 Gray 코드를 배운 이유가 여기!)
- 메모상 "칩 안 = 동기 / 칩 밖 = 비동기"로 적었는데, 정확히는 **클럭이 같으냐 다르냐**로 구분. 칩 안에도 클럭 도메인이 여러 개면 비동기 FIFO를 쓴다. 칩 밖(외부 인터페이스)과 만나는 경계가 대표적인 비동기 FIFO 사용처라는 의미로 이해하면 됨.

#### ④ MCP (Multi-Cycle Path) Formulation / Handshaking
```
송신(A)                     수신(B)
data 준비, 고정 ─────────────→ (data는 여러 클럭 동안 안 바뀜)
req = 1  ──[2-FF sync]──→   req 감지 → data 캡처
         ←──[2-FF sync]──   ack = 1
ack 감지 → req = 0
         ...                ack = 0  → 다음 전송 가능
```
- 데이터 자체는 동기화하지 않고, **제어 신호(req/ack) 1bit만 동기화**
- 데이터가 수신 측에서 캡처될 때까지 **안정적으로 유지**되므로 멀티 bit도 안전
- 응답이 올 때까지 기다리므로 느림 → 가끔 바뀌는 설정값/레지스터 전달에 적합

> **면접 답변 템플릿**
> "CDC는 비동기 클럭 도메인 간 신호 전달 시 setup/hold 위반으로 메타스테이빌리티가 생기는 문제입니다. 1bit 제어 신호는 2-FF synchronizer로 MTBF를 높이고, 펄스는 toggle synchronizer로 놓치지 않게 합니다. 멀티 bit는 비트 간 skew 때문에 각각 동기화하면 안 되고, 연속 데이터는 Gray 코드 포인터를 쓰는 비동기 FIFO, 간헐적 데이터는 req/ack handshake를 사용합니다. 그리고 CDC 경로는 STA에서 false path로 처리하고 CDC 검증 툴(Spyglass 등)로 확인합니다."

## 3. Propagation Delay (전파 지연)

입력이 바뀐 뒤 출력이 바뀌기까지 걸리는 시간.

- 게이트: `tpLH`(Low→High), `tpHL`(High→Low), 보통 `tpd = (tpLH + tpHL)/2`
- **Contamination delay (tcd)**: 출력이 **처음 변하기 시작**하는 최소 지연 (hold 분석에 사용)
- FF: `tclk-q`

### 타이밍 제약 (동기 회로의 핵심 공식)
```
FF1 ──[조합 논리]── FF2
```
- **Setup 조건** (최대 지연): `Tclk ≥ tclk-q + tcomb(max) + tsu (+ skew 영향)`
  → 위반 시: 클럭 낮추기, 파이프라이닝, 조합 논리 줄이기
  → 최대 동작 주파수 `fmax = 1 / (tclk-q + tcomb + tsu)`
- **Hold 조건** (최소 지연): `tclk-q + tcomb(min) ≥ th (+ skew 영향)`
  → 위반 시: 지연 버퍼 삽입 (클럭을 낮춰도 해결 안 됨!)

## 4. Glitch

- **정의**: 조합 논리에서 입력들이 거치는 **경로 지연이 서로 달라** 출력에 잠깐 생기는 **원치 않는 짧은 펄스** (hazard라고도 함)
  - 외부 노이즈가 아니라 **회로 내부 구조 때문에 생기는** 고주파성 펄스
```
A ‾‾‾‾‾|_______        Y = A & B, B = ~A (B가 조금 늦게 바뀜)
B _______|‾‾‾‾‾        
Y _____|‾|_____  ← 원래 항상 0이어야 하는데 잠깐 1
```
- **해결**
  - **플립플롭을 통과시키면 없어짐**: FF는 클럭 엣지에서만 샘플링하므로, 엣지 전에 글리치가 가라앉으면 무시됨 → 출력을 레지스터로 받는 이유
  - **Glitch-free clock mux**: 클럭을 MUX로 전환할 때 짧은 클럭 펄스가 생기지 않게 하는 구조
  - **비교기(==, <) 출력, 디코더 출력** 같은 조합 출력은 글리치가 많음 → 그 출력으로 **클럭, 리셋, 래치 enable을 직접 구동하면 절대 안 됨**

## 5. 조합 논리(CL) vs 순차 논리(SL)

| 구분 | CL (Combinational Logic) | SL (Sequential Logic) |
|---|---|---|
| 출력 결정 | **현재 입력만**으로 결정 | 현재 입력 + **이전 상태(기억)** |
| 메모리 | 없음 | 있음 (FF, latch) |
| 클럭 | 불필요 | 필요 (동기식) |
| 예 | MUX, 디코더, 가산기, 비교기 | 카운터, 레지스터, 시프트 레지스터, FSM |
| Verilog | `assign`, `always @(*)` + `=` | `always @(posedge clk)` + `<=` |

## 6. 플립플롭의 장점 / 단점 / 특징

**장점**
- **글리치 제거**: 클럭 엣지에서만 값을 받아서 조합 논리의 글리치가 다음 단으로 안 넘어감
- 모든 동작이 클럭에 **동기화** → 타이밍 예측·분석(STA)이 쉬움
- 상태 저장 가능 → FSM, 카운터 등 구현
- 긴 조합 경로를 끊어(파이프라이닝) **동작 주파수↑**

**단점**
- 출력이 **클럭 사이클만큼 늦어짐** (latency 증가)
- 면적/비용↑ (게이트 수가 많음, 래치 2개 분량)
- 클럭이 계속 토글 → **전력 소모·발열↑** (칩 전력의 큰 비중이 클럭 트리)
- 클럭 스큐/지터 관리 필요

## 7. 동기식 순차회로 (Synchronous Sequential Circuits)

- 모든 FF가 **같은 클럭 엣지**에서 동시에 상태를 바꾸는 회로
- 구조: `입력 → [조합 논리] → [FF] → 출력`, FF 출력이 다시 조합 논리로 **피드백**
- 비동기 순차회로(FF 출력을 다른 FF 클럭으로 쓰는 리플 카운터 등)는 타이밍 분석이 어려워 실무에서는 피한다

### 디지털 설계 = Datapath + Control
```
         ┌────────── Control Unit (FSM) ──────────┐
         │  상태에 따라 제어 신호 생성              │
         └───┬──────────┬──────────┬──────────────┘
             │sel       │en        │op         ↑ status (zero, done, ...)
         ┌───▼──────────▼──────────▼─────────────┴┐
data ──→ │ Datapath: 레지스터, MUX, ALU, 카운터     │──→ result
         └─────────────────────────────────────────┘
```
- **Datapath**: 데이터를 실제로 저장·연산·이동시키는 부분 (지금까지 만든 것: 가산기, 시프트 레지스터, 카운터 …)
- **Control**: datapath에 "언제 무엇을 할지" 제어 신호를 주는 부분 → **FSM**으로 설계

## 8. FSM (Finite State Machine) 구조 — 피드백 구조

```
         ┌──────────────────────────────┐
         │                              │ (feedback: 현재 상태)
input ──→│ Next State Logic (CL) ──→ [State Register (SL)] ──┬──→ Output Logic (CL) ──→ output
         └──────────────────────────────────────────────────┘
```

| | Moore | Mealy |
|---|---|---|
| 출력 | **현재 상태만**으로 결정 | 현재 상태 + **현재 입력** |
| 반응 | 1클럭 늦음 | 입력에 즉시 반응 |
| 상태 수 | 많아지는 편 | 적은 편 |
| 글리치 | 출력 안정적 | 입력 글리치가 출력에 전달될 수 있음 |

### 상태 인코딩
- **Binary**: 상태 수 N → `$clog2(N)`비트, FF 최소
- **Gray**: 순차적으로 전이하는 FSM에서 토글 적음 → 저전력
- **One-hot**: 상태당 FF 1개, 디코딩 로직 간단·빠름 → **FPGA에서 선호**

### 예제: "101" 시퀀스 검출기 (Moore, 겹침 허용)
```verilog
module seq101 (
    input      clk, rst_n, din,
    output reg detect
);
    localparam S0 = 2'd0,   // 아무것도 없음
               S1 = 2'd1,   // "1"
               S2 = 2'd2,   // "10"
               S3 = 2'd3;   // "101" 검출

    reg [1:0] state, next_state;

    // ① State Register (순차)
    always @(posedge clk or negedge rst_n)
        if (!rst_n) state <= S0;
        else        state <= next_state;

    // ② Next State Logic (조합)
    always @(*) begin
        next_state = state;            // 기본값 → latch 방지
        case (state)
            S0: next_state = din ? S1 : S0;
            S1: next_state = din ? S1 : S2;
            S2: next_state = din ? S3 : S0;
            S3: next_state = din ? S1 : S2;   // 겹침: "10101"
            default: next_state = S0;
        endcase
    end

    // ③ Output Logic (Moore: 상태만으로)
    always @(*) detect = (state == S3);
endmodule
```
- 이렇게 **3개 always로 나누는 스타일**이 가독성·유지보수에 좋고 가장 일반적
- 출력 글리치가 문제되면 ③을 레지스터 출력으로 바꿈 (registered output)

## 9. 파이프라인 (Pipeline) 구조

긴 조합 논리 중간에 **레지스터를 삽입**해 여러 단계로 나누는 구조.

```
비파이프라인:  [FF] ── 조합 30ns ── [FF]               → fmax ≈ 33MHz
파이프라인:    [FF] ─ 10ns ─ [FF] ─ 10ns ─ [FF] ─ 10ns ─ [FF]  → fmax ≈ 100MHz
```
- **Throughput(처리량)↑**: 매 클럭 새 데이터를 넣을 수 있음
- **Latency(지연)↑**: 결과가 나오기까지 N클럭
- 면적↑ (레지스터 추가)
- 주의: 데이터 의존성(hazard), 제어 신호도 같은 단수만큼 지연시켜 맞춰야 함
- FSM이 "피드백 구조"라면, 파이프라인은 "앞으로만 흐르는(feed-forward) 구조"

## 10. Clock Phase / Delay — Skew와 Jitter

- **Clock Skew**: 같은 클럭이 **서로 다른 FF에 도착하는 시간 차이** (배선 길이, 버퍼 차이 때문)
  - 수신 FF에 클럭이 늦게 도착 → setup엔 유리, hold엔 불리
  - 수신 FF에 클럭이 일찍 도착 → setup엔 불리, hold엔 유리
- **Clock Jitter**: 클럭 엣지가 이상적인 위치에서 **사이클마다 흔들리는** 것 (PLL 노이즈 등)
- 둘 다 타이밍 마진을 깎아먹음 → STA에서 uncertainty로 반영

## 11. CTS (Clock Tree Synthesis)

- 물리 설계(Place & Route) 단계에서 클럭 소스부터 수천~수백만 개 FF까지 **버퍼 트리를 만들어 클럭을 분배**하는 과정
- 목표: **skew 최소화**, 적절한 transition(slew), 전력 최소화
- 구조 예: **H-tree** (대칭 구조로 모든 말단까지 거리 동일)
- 흐름: `합성 → Placement → **CTS** → Routing → STA/Signoff`
- RTL 설계자 입장에서 알아둘 것: 클럭을 조합 논리로 만들거나 게이팅을 임의로 하면 CTS가 어려워짐 → 클럭 게이팅은 전용 ICG 셀 사용, 클럭 분주는 enable 방식 권장

```verilog
// ❌ 조합 논리로 클럭 생성/게이팅
assign gclk = clk & en;

// ✅ 클럭은 그대로, enable로 제어
always @(posedge clk)
    if (en) q <= d;
```
