## 1. bufif0 — 3상태(tri-state) 버퍼 프리미티브

출력을 0, 1뿐 아니라 **z(high impedance, 연결 끊김)** 로도 만들 수 있는 버퍼. 여러 소자가 **하나의 버스를 공유**할 때 사용한다.

| 프리미티브 | 동작 | control=0 | control=1 |
|---|---|---|---|
| `bufif0` | 버퍼, **active-low** enable | out = in | out = **z** |
| `bufif1` | 버퍼, active-high enable | out = **z** | out = in |
| `notif0` | 인버터, active-low enable | out = ~in | out = **z** |
| `notif1` | 인버터, active-high enable | out = **z** | out = ~in |

```verilog
// 포트 순서: (출력, 입력, 제어)
bufif0 b0 (out, in, ctrl);

// 지연까지 지정: #(rise, fall, turn-off)
bufif0 #(3, 4, 5) b1 (out, in, ctrl);
// 0→1: 3, 1→0: 4, →z: 5 시간 단위

// assign으로 같은 동작
assign out = (ctrl == 1'b0) ? in : 1'bz;
```

- control이 x나 z일 때 출력은 `x`, `0/z`, `1/z` 같은 불확정 값이 될 수 있다.
- 실제 칩 내부에서는 tri-state 버스를 거의 쓰지 않고 MUX로 대체한다(타이밍과 테스트 문제 때문). tri-state는 주로 **I/O 패드(inout 포트)** 에서 쓴다.
- FPGA도 내부 tri-state는 MUX로 바꿔서 합성하고, 실제 tri-state는 IOB(I/O 블록)에만 있다.

## 2. 지연(Delay)이란?

**신호가 입력에서 출력까지 전달되는 데 걸리는 시간.** 실제 회로에서는 게이트 스위칭 시간과 배선 RC 때문에 반드시 생긴다.

### 2.1 FPGA vs 칩(ASIC)에서의 지연
- Verilog의 `#지연`은 **합성되지 않는다.** 합성 툴은 `#`을 무시하므로 FPGA든 ASIC이든 RTL의 `#` 지연은 시뮬레이션에서만 의미가 있다.
- **FPGA**: 지연은 툴이 배치·배선 후 알아서 계산하고, 설계자는 타이밍 제약(XDC/SDC)만 준다. 그래서 RTL에 지연을 거의 쓰지 않는다.
- **칩(ASIC)**: 지연을 훨씬 정밀하게 다룬다.
  - 표준 셀 라이브러리(.lib)에 셀별 지연이 정의되어 있다.
  - P&R 후 추출한 실제 지연을 **SDF 파일**로 넷리스트에 역주석(back-annotation)해서 **게이트 레벨 시뮬레이션**을 한다.
  - 셀 모델 자체에 `specify` 블록으로 핀-핀 지연이 들어 있다.
  - 아날로그/메모리 등 하드 IP의 동작 모델에도 지연을 넣는다.
- 테스트벤치에서는 둘 다 지연을 자주 쓴다. (`#10 rst_n = 1;`, 입력에 약간의 지연을 줘서 클럭 엣지와 겹치지 않게 하는 등)

### 2.2 입력 지연 / 출력 지연 (타이밍 제약 관점)
칩(또는 FPGA) 밖에서 생기는 지연을 STA 툴에 알려주는 값.

```
 [외부 칩 FF] ──외부 로직/보드 배선──→ |입력 포트| ── 내부 로직 ──→ [내부 FF]
              |←── input delay ───→|
 
 [내부 FF] ── 내부 로직 ──→ |출력 포트| ──보드 배선/외부 로직──→ [외부 칩 FF]
                                 |←──── output delay ────→|
```

- **입력 지연 (`set_input_delay`)**: 클럭 엣지 후 외부 신호가 **우리 칩의 입력 핀에 도착하기까지** 이미 소모된 시간이다. 그 나머지 시간 안에 내부 경로가 끝나야 한다.
- **출력 지연 (`set_output_delay`)**: 우리 칩 출력 핀에서 나간 신호가 **외부 소자에서 setup을 만족하는 데 필요한 시간**이다. 그만큼 내부 경로를 빨리 끝내야 한다.

```tcl
create_clock -period 10 [get_ports clk]
set_input_delay  3 -clock clk [get_ports din]    ; # 내부에 7ns 남음
set_output_delay 2 -clock clk [get_ports dout]   ; # 내부는 8ns 안에
```

### 2.3 Verilog에서 지연 표현
- `#5` : 단일 지연
- `#(3, 4)` : rise 3, fall 4
- `#(3, 4, 5)` : rise, fall, turn-off(→z)
- `#(1:2:3)` : **min:typ:max** 지연. 시뮬레이터 옵션으로 어떤 값을 쓸지 고른다.

## 3. 할당문의 종류

| 종류 | 대상(좌변) | 키워드 | 주 용도 |
|---|---|---|---|
| **연속 할당** | **net** (wire 등) | `assign` | 조합 논리 |
| **절차형 할당** | **variable** (reg, integer 등) | `always`, `initial`, task, function 안 | 조합/순차 논리, 테스트벤치 |
| **절차형 연속 할당** | variable 또는 net | `assign-deassign`, `force-release` | 디버깅, 테스트벤치 |

### 3.1 연속 할당 (continuous assignment)
- **net 자료형**에 값을 할당하고, 우변이 바뀔 때마다 **항상 다시 계산**된다. 실제 배선처럼 계속 구동된다고 생각하면 된다.
- 조합 논리 모델링에 주로 쓴다.
```verilog
assign y   = a & b;
assign sum = a + b;
assign out = sel ? d1 : d0;
```

### 3.2 절차형 할당 (procedural assignment)
- `always`, `initial` 블록 안에서 **variable 자료형**(reg 등)에 값을 할당한다.
- 블록이 실행될 때만 값이 바뀌고, 다음에 다시 할당될 때까지 **값을 유지**한다.

#### Blocking (`=`) vs Non-blocking (`<=`)

| | Blocking `=` | Non-blocking `<=` |
|---|---|---|
| 실행 | 한 줄씩 **즉시** 계산하고 즉시 좌변 갱신 | 우변은 즉시 계산, **좌변 갱신은 타임스텝 끝(NBA 영역)으로 미룸** |
| 다음 문장 | 앞 문장이 끝나야 실행됨 (blocking = 막는다) | 기다리지 않고 바로 다음 문장 진행 |
| 순서 영향 | 문장 순서가 결과에 **영향 있음** | 모든 좌변이 동시에 갱신돼서 순서가 결과에 **영향 없음** |
| 용도 | **조합 논리** (`always @(*)`) | **순차 논리** (`always @(posedge clk)`) |

> 메모 보정: non-blocking은 "비동기"나 "딜레이를 주는 것"이 아니다. 같은 시간 안에서 **모든 값을 먼저 읽고, 나중에 한꺼번에 갱신**하는 방식이다. 같은 클럭 엣지에서 여러 플립플롭이 **동시에** 값을 바꾸는 하드웨어 동작을 흉내 내기 위한 것이다. 문장 자체는 위에서 아래로 실행되지만, 갱신이 동시에 일어나서 결과적으로 순서가 상관없어진다.

**대표 예제: 값 교환(swap)**
```verilog
// Blocking: 교환 실패
always @(posedge clk) begin
    a = b;      // a ← b
    b = a;      // b ← (이미 바뀐) a = b  → 둘 다 b
end

// Non-blocking: 교환 성공 (FF 2개가 서로 물고 있는 회로)
always @(posedge clk) begin
    a <= b;     // 둘 다 엣지 직전 값을 읽고
    b <= a;     // 타임스텝 끝에 동시에 갱신
end
```

**시프트 레지스터 예제**
```verilog
// Non-blocking: 정상적인 3단 시프트 레지스터 (FF 3개)
always @(posedge clk) begin
    q1 <= d;
    q2 <= q1;
    q3 <= q2;
end

// Blocking: d가 한 클럭에 q3까지 그대로 통과 → FF 1개처럼 동작
always @(posedge clk) begin
    q1 = d;
    q2 = q1;
    q3 = q2;
end
```

#### 레이스 컨디션 (Race Condition)
같은 시뮬레이션 시간에 실행되는 여러 블록의 **실행 순서가 정해져 있지 않아서**, 시뮬레이터마다(또는 실행할 때마다) 결과가 달라지는 현상이다.
```verilog
// ❌ 레이스: 어느 always가 먼저 실행되느냐에 따라 b 값이 달라짐
always @(posedge clk) a = d;
always @(posedge clk) b = a;

// ✅ non-blocking으로 해결: 항상 b는 이전 a
always @(posedge clk) a <= d;
always @(posedge clk) b <= a;
```

**코딩 규칙 (Cummings 가이드라인, 면접에도 자주 나옴)**
1. 순차 논리 → `<=`
2. 조합 논리 → `=`
3. 한 always 블록 안에서 `=`와 `<=`를 섞지 않는다.
4. 같은 변수를 여러 always 블록에서 할당하지 않는다.
5. `$display`로 `<=` 결과를 확인하려면 `$strobe`를 쓴다.

### 3.3 절차형 연속 할당 (procedural continuous assignment)
절차 블록 안에서 실행되지만, 한번 실행되면 **해제될 때까지 연속으로 값을 강제 구동**한다.

| 구문 | 대상 | 설명 |
|---|---|---|
| `assign` / `deassign` | variable만 | 일반 절차형 할당을 덮어쓰고 값을 고정한다. **비권장(SystemVerilog에서 deprecated)** |
| `force` / `release` | variable, **net 모두** | 가장 강력하다. assign과 일반 할당을 모두 덮어쓴다. |

```verilog
// 테스트벤치에서 DUT 내부 신호를 강제로 고정해 디버깅
initial begin
    #100 force tb.u_dut.u_fsm.state = 2'b11;   // 특정 상태 강제
    #50  release tb.u_dut.u_fsm.state;         // 원래대로
end
```
- 합성되지 않는다. **테스트벤치나 디버깅 전용**이다.
- 에러 주입(fault injection), 도달하기 어려운 상태 테스트에 쓴다.
- release 후 variable은 다음 할당 때까지 강제값을 유지하고, net은 즉시 원래 드라이버 값으로 돌아간다.

## 4. 할당 지연과 net 지연

### 4.1 연속 할당에서의 지연

```verilog
// ① 할당 지연 (assignment delay): 해당 assign 문에만 적용
assign #5 y = a & b;

// ② net 지연 (net delay): net 선언문에서 지연값 지정
//    이 net을 구동하는 모든 드라이버의 변화에 적용
wire #5 y;
assign y = a & b;

// ③ net 선언 할당: 선언과 assign을 한 번에 (①과 같은 효과)
wire #5 y = a & b;

// ①과 ②를 같이 쓰면 지연이 더해짐
wire #3 y;
assign #2 y = a & b;   // 총 5
```
- 할당 지연은 **문장 단위**이고, net 지연은 **배선 자체의 지연**이다. 여러 드라이버가 있는 버스에서 차이가 난다.

### 4.2 절차형 할당에서의 지연

```verilog
// 할당문 간 지연 (inter-assignment / regular delay)
#5 y = a;       // 5만큼 기다린 뒤, 그때의 a를 읽어 할당

// 할당문 내 지연 (intra-assignment delay)
y = #5 a;       // 지금 a를 읽어두고, 5 뒤에 y에 할당
y <= #5 a;      // 지금 a를 읽고 5 뒤에 갱신, 다음 문장은 바로 진행
```

| 형태 | 우변 읽는 시점 | 할당 시점 | 다음 문장 |
|---|---|---|---|
| `#5 y = a;` | 5 후 | 5 후 | 5 후 |
| `y = #5 a;` | **지금** | 5 후 | 5 후 |
| `y <= #5 a;` | **지금** | 5 후 | **지금** |

## 5. 관성 지연 (Inertial Delay) vs 전송 지연 (Transport Delay)

### 관성 지연: Verilog HDL의 기본(default)
- **지연값보다 짧은 펄스는 출력에 나타나지 않고 걸러진다.**
- 실제 게이트는 너무 짧은 입력 변화에 반응할 시간이 부족한데, 이것을 모델링한 것이다.
- `assign #d`, 게이트 프리미티브 지연, net 지연이 모두 관성 지연이다.

```verilog
assign #5 y = a;

a : ___|‾‾|__________      (폭 2인 펄스)
y : _________________      → 5보다 짧아서 사라짐

a : ___|‾‾‾‾‾‾‾‾|____      (폭 8인 펄스)
y : ________|‾‾‾‾‾‾‾‾|_    → 5만큼 밀려서 그대로 전달
```

### 전송 지연
- **모든 변화를 그대로, 지연만큼 밀어서 전달**한다. 펄스가 짧아도 사라지지 않는다.
- 긴 배선이나 지연선(delay line)을 모델링할 때 쓴다.
- Verilog에는 전용 키워드가 없고, **non-blocking 할당 내 지연**으로 모델링한다.
```verilog
always @(a) y <= #5 a;    // 전송 지연 모델
```

> 💡 VHDL은 `after`(관성)와 `transport after`(전송)로 키워드가 따로 있다. Verilog는 위처럼 구현 방식으로 구분한다.

## 6. 클럭 분배 (Clock Distribution)

하나의 클럭 소스를 칩 안의 **수많은 플립플롭에 같은 타이밍으로** 전달하는 것이다.

- 문제: 클럭 하나가 수천~수백만 개 FF를 구동해야 해서 fanout이 크고 배선이 길어진다. 그 결과 지연이 커지고 **skew**가 생긴다.
- **칩(ASIC)**: P&R 단계의 **CTS(Clock Tree Synthesis)** 가 버퍼 트리(H-tree 등)를 자동으로 만들어 skew를 최소화한다. (지난 시간 내용)
- **FPGA**: 이미 만들어진 **전용 글로벌 클럭 네트워크**를 쓴다.
  - Xilinx: `BUFG`(글로벌 버퍼), `BUFR`/`BUFIO`(지역 버퍼), `MMCM`/`PLL`(주파수 합성, 위상 조정)
  - 클럭 입력 핀은 반드시 **클럭 전용 핀(CC pin)** 에 연결해야 글로벌 네트워크를 탈 수 있다.
- 일반 로직 배선으로 클럭을 보내면 skew가 커서 타이밍이 깨진다. 그래서 클럭은 항상 전용 경로로 보낸다.

## 7. Datapath 경로 vs Control Signal

### 7.1 설계 구조 관점
- **Datapath**: 실제 데이터가 흐르며 저장·연산되는 경로 (레지스터 → MUX → ALU → 레지스터)
- **Control signal**: datapath를 조종하는 신호 (MUX select, 레지스터 enable, ALU opcode, write enable, reset 등). 보통 **FSM**이 만든다.

### 7.2 타이밍 분석(STA) 관점
타이밍 경로를 볼 때 경로를 세 가지로 나눈다.
```
           ┌─── clock path (launch) ───┐
CLK 소스 ──┤                           ▼
           │                       [FF1] ──── data path ────→ [FF2]
           └─── clock path (capture) ───────────────────────────▲
```
- **Data path**: 출발 FF의 Q부터 도착 FF의 D까지 (tclk-q + 조합 논리 지연)
- **Clock path**: 클럭 소스부터 각 FF의 CLK 핀까지 (이 경로들의 차이가 **skew**)
- 타이밍 검사는 data path의 **도착 시간(arrival)** 과 클럭으로 정해지는 **요구 시간(required)** 을 비교해 slack을 구한다.
  - `slack = required time - arrival time`, **음수면 위반**

### 7.3 주의할 control signal
- **Reset**: 비동기 리셋은 **비동기 assert, 동기 deassert**(reset synchronizer)로 처리한다. 리셋 해제가 클럭과 겹치면 메타스테이빌리티가 생기기 때문이다.
- **Enable, select** 같은 control 신호는 fanout이 커서 타이밍 크리티컬 경로가 되기 쉽다. 필요하면 레지스터를 복제(duplication)한다.

## 8. 클럭 분주기 (Clock Divider)

입력 클럭 주파수를 1/N로 낮추는 회로이다.

### 8.1 2분주 (토글 FF)
```verilog
always @(posedge clk or negedge rst_n)
    if (!rst_n) clk_div2 <= 1'b0;
    else        clk_div2 <= ~clk_div2;    // f/2, duty 50%
```

### 8.2 2^n 분주 (카운터의 상위 비트)
```verilog
reg [3:0] cnt;
always @(posedge clk) cnt <= cnt + 1'b1;
// cnt[0]: f/2, cnt[1]: f/4, cnt[2]: f/8, cnt[3]: f/16
```

### 8.3 N 분주 (짝수, duty 50%)
```verilog
module clk_div #(parameter N = 10) (    // N은 짝수
    input      clk, rst_n,
    output reg clk_out
);
    reg [$clog2(N/2)-1:0] cnt;
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            cnt <= 0; clk_out <= 1'b0;
        end else if (cnt == N/2 - 1) begin
            cnt <= 0; clk_out <= ~clk_out;   // N/2마다 토글
        end else begin
            cnt <= cnt + 1'b1;
        end
    end
endmodule
```
- 홀수 분주에서 duty 50%가 필요하면 posedge 카운터와 negedge 카운터 출력을 OR로 조합한다.

### 8.4 ⚠️ 실무 주의: 분주한 신호를 클럭으로 쓰지 말 것 (특히 FPGA)
- 로직으로 만든 클럭은 글로벌 클럭 네트워크를 타지 못해 **skew가 크다**.
- 원래 클럭과 분주 클럭 사이에 **CDC 비슷한 문제**가 생기고, 타이밍 분석도 복잡해진다.
- **권장 방법 1: Clock Enable 방식.** 클럭은 그대로 두고, N클럭마다 1클럭짜리 enable 펄스를 만든다.
```verilog
reg [$clog2(N)-1:0] cnt;
wire tick = (cnt == N-1);              // N클럭마다 1클럭 동안 1
always @(posedge clk) cnt <= tick ? 0 : cnt + 1'b1;

always @(posedge clk)
    if (tick) slow_reg <= slow_reg + 1'b1;   // 느린 동작, 클럭은 하나
```
- **권장 방법 2**: 진짜 다른 주파수의 클럭이 필요하면 **PLL/MMCM**을 쓴다.
- 칩에서 분주 클럭을 쓸 때는 SDC에 `create_generated_clock`으로 반드시 정의해야 STA가 정확히 분석한다.
- 지난 시간 debouncer의 10ms 카운터, UART의 baud rate 생성도 모두 이 **tick(enable) 방식**으로 만드는 것이 정석이다.
